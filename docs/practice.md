# Самостоятельная практика: рабочие задачи

<p class="reading-time">Примерное время · Чтение: 4–6 мин</p>

Для каждого задания сначала определите данные, правила, результат и отказы. Подготовьте небольшой учебный набор без реальных персональных данных. Решения ищите через темы методички, а затем адаптируйте самостоятельно.

## 1. Стоимость упаковки

**После:** [арифметики](start.md), [условий](conditions-errors.md), [циклов](loops.md).

Мастерская отправляет товары коробками по 6 штук. Рассчитайте число коробок с учётом последней неполной, расход бумаги и стоимость. Количество неотрицательное, цены заданы в копейках.

**Приёмка:** 0 товаров → 0 коробок, 6 → 1, 7 → 2. Отрицательный ввод отклоняется, единицы денег не смешиваются.

## 2. Закупка на склад

**После:** [коллекций](collections.md), [функций](functions.md).

У товара есть артикул, остаток и минимальный запас. Сформируйте список закупки до минимального запаса, отсортированный по артикулу.

**Приёмка:** остаток 2 при минимуме 5 → докупить 3; остаток 5 не включается. Повтор артикула и отрицательный остаток отклоняются.

## 3. Бронирование мест

**После:** [таблиц](games.md), [состояний](state-files.md).

Зал состоит из 5 рядов по 8 мест. Реализуйте просмотр, бронь и отмену по координате. Пользователь видит номера с единицы, программа хранит индексы с нуля.

**Приёмка:** повторная бронь отклоняется; отрицательная координата не обращается к последнему месту; отмена меняет только выбранную клетку.

## 4. Проверка прайс-листа

**После:** [строк](strings.md), [файлов](files-errors.md), [валидации](dates-validation.md).

Прочитайте CSV с кодом, названием, ценой и датой. Очистите края строк, проверьте типы, обязательные поля и уникальность. Сохраните отчёт об ошибках с номерами строк.

**Приёмка:** разделитель внутри названия читается корректно; неверная дата и цена не принимаются; исходный файл остаётся доступным.

## 5. Каталог услуг

**После:** [dataclass](dataclasses-crud.md), [CRUD](crud.md), [архитектуры](architecture.md).

Добавьте создание, поиск, обновление и удаление услуг. У записи стабильный ID, у функции — ясный результат. Меню находится отдельно от операций.

**Приёмка:** сортировка не меняет ID; после удаления новый ID не повторяет прежний; отказ обновления сохраняет старые поля.

## 6. Хранение и экспорт

**После:** [сериализации](storage.md), [консольного UI](ui.md).

Сделайте служебное сохранение каталога и отдельный читаемый отчёт. Восстановите даты и последний выданный ID после перезапуска.

**Приёмка:** пустой каталог загружается, повреждённый файл не заменяется автоматически пустым, ID не откатывается после удаления записи.

## 7. Поиск для администратора

**После:** [поиска и сортировки](search-sort.md), [lambda и генераторов](functional-tools.md).

Соедините поиск по названию, фильтр категории и диапазон цены. Результат сортируйте по рейтингу с дополнительным ключом ID.

**Приёмка:** пустой запрос и перевёрнутый диапазон имеют явное поведение; равные рейтинги дают предсказуемый порядок; основной каталог не меняется.

## 8. Сбор учебного HTML

**После:** [парсинга](parsing.md).

Создайте HTML нескольких карточек услуг и извлеките название, код и цену. Сетевую загрузку отделите от разбора.

**Приёмка:** пропущенное поле обнаруживается в своей карточке; списки полей не рассогласуются; отсутствие карточек отличается от повреждения карточки.

## 9. Клиент внешнего API

**После:** [HTTP API](api.md).

Сделайте клиент выбранного учебного справочника. Преобразуйте ответ в свою модель и подготовьте искусственные ответы для проверки без интернета.

**Приёмка:** пустые данные, timeout, HTTP-ошибка и неверная структура различаются. В коде нет действующих ключей.

## 10. Бот записи на услугу

**После:** [обработчиков](bot-events.md), [FSM](bot-ui.md), [макетов](bot-design.md).

Сценарий: услуга → дата → время → проверка → подтверждение. Добавьте отмену, возврат и просмотр своих записей.

**Приёмка:** два пользователя не смешивают контекст; неправильный ввод остаётся на своём шаге; старая кнопка не создаёт повторную запись; подтверждённое сохраняется после перезапуска.

## 11. Развёртывание бота

**После:** [Docker](docker.md).

Подготовьте requirements.txt, Dockerfile, .dockerignore, Compose и инструкцию переменных окружения. Подключите постоянный путь данных.

**Приёмка:** другой ученик запускает проект по README; токен не включён в образ; запись переживает пересоздание контейнера; логи позволяют проверить старт.

## 12. Свой бизнес-проект

**После:** [разработки приложения](final-project.md), [технической защиты](defense.md).

Выберите склад, журнал ремонта, каталог, запись клиентов или учёт задач. Подготовьте пользователя, минимальные сценарии, модель, макеты и критерии приёмки. Реализуйте одну версию целиком, затем расширяйте.

**Приёмка:** есть рабочий путь от ввода до сохранённого результата, проверки отказов, инструкция запуска и понятное объяснение ограничений.

## Как сдавать

Приложите исходники, README, учебные данные и таблицу «вход → ожидаемый результат → фактический результат». Для каждого сценария покажите обычный случай, границу и отказ. Если правило не определено, сначала письменно зафиксируйте своё соглашение.
