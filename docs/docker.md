# Docker, Compose и запуск Python-приложения

<p class="reading-time">Примерное время · Чтение: 5–8 мин · Практика: 50–90 мин</p>

!!! abstract "Фокус"
    - **Нужно знать:** образ, контейнер, Dockerfile, зависимости, окружение, том и логи.
    - **Нужно уметь:** воспроизвести запуск приложения и сохранить файлы между контейнерами.

## Теория

Docker упаковывает приложение с выбранным окружением. Образ — подготовленный шаблон, контейнер — запущенный экземпляр. Это помогает одинаково установить зависимости на компьютере и сервере, но не исправляет ошибки самого кода.

### Подготовка проекта

Нужны main.py, requirements.txt с проверенными зависимостями и конфигурация через окружение. Requirements-docs.txt относится к сайту методички, а не к вашему боту. Запуск лучше защитить if __name__=="__main__", чтобы импорт модуля не начинал polling.

### Слои Dockerfile

From выбирает базовый образ Python. Workdir задаёт рабочую папку. Copy переносит файлы. Run выполняется при сборке, Cmd — при запуске контейнера. Сначала копируют requirements и устанавливают пакеты, затем исходники: это позволяет повторно использовать слой зависимостей, когда изменился только код.

### Что исключить

.dockerignore не допускает в сборку .env, .git, .venv, __pycache__ и локальные данные. .gitignore регулирует Git и не заменяет .dockerignore. Если секрет попал в COPY, он может остаться в слоях образа.

### Конфигурация

Токен читайте из os.environ["TELEGRAM_BOT_TOKEN"]. Локальный .env может использовать Compose для подстановки. Наличие файла .env само по себе не добавляет все значения в окружение приложения: укажите environment либо env_file.

### Файлы переживают контейнер

Если каталог пишет в /app/data, подключите том к этому пути. Файл, оставленный только в изменяемом слое удалённого контейнера, не является надёжным постоянным хранилищем. Том также требует резервного копирования. Не используйте down -v для обычного перезапуска, если в томе важные данные.

### Порядок запуска

Сначала проверьте приложение локально, затем сборку, затем контейнер. Docker compose ps показывает состояние, logs — сообщения процесса. «Контейнер запущен» не доказывает, что бот отвечает; пройдите реальный сценарий.

Для long polling обычно не нужен входящий порт, потому что бот сам обращается к Telegram. Не запускайте одновременно локальный и серверный polling для одного токена. При переносе на VPS сначала настройте доступ к серверу и Docker по документации провайдера, затем повторите тот же проверенный запуск. Адрес, ОС и тариф сервера не являются частью Python-кода.

## Частые ошибки

Не включайте секреты в COPY. Не путайте RUN и CMD. Не считайте том резервной копией. Не отправляйте в серверный образ виртуальное окружение с другого компьютера.

## Разбор практических задач

Сначала запишите свой план и ожидаемый результат, затем сравните с разбором.

### Задача 1. Образ

#### Условие

Соберите окружение приложения с main.py и requirements.txt.

#### Как рассуждать и алгоритм

Разделите зависимости и код, а секреты исключите из контекста.

#### Решение

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
ENV PYTHONUNBUFFERED=1
CMD ["python", "main.py"]
```

#### Проверка

docker build -t school-bot . завершает сборку. До этого создайте .dockerignore с .env, .git, .venv, __pycache__ и data.

### Задача 2. Compose и данные

#### Условие

Передайте токен и сохраните каталог вне слоя контейнера.

#### Как рассуждать и алгоритм

Имя BOT_DATA_FILE задаёт путь, который приложение должно действительно читать при сохранении.

#### Решение

```yaml
services:
  bot:
    build: .
    environment:
      TELEGRAM_BOT_TOKEN: ${TELEGRAM_BOT_TOKEN:?set token}
      BOT_DATA_FILE: /app/data/catalog.json
    volumes:
      - bot_data:/app/data
volumes:
  bot_data:
```

#### Проверка

Создайте локальный .env без публикации в Git. В коде читайте BOT_DATA_FILE. Само подключение тома не меняет путь записи программы.

### Задача 3. Проверка работы

#### Условие

Запустите контейнер и проверьте его сообщения.

#### Как рассуждать и алгоритм

Остановите другой экземпляр этого же бота. После запуска пройдите /start и один сценарий.

#### Решение

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=50 bot
```

#### Проверка

Бот отвечает, файл появляется в подключённом пути. После down и up без -v запись остаётся.

## Самостоятельная практика

Упакуйте своего бота: инструкция конфигурации, сборка, запуск, логи, остановка, повторный запуск. Подтвердите сохранение одной учебной записи и корректное сообщение при отсутствии обязательной переменной.
