# HTTP API, проверка ответа и ошибки сети

## Теория

API позволяет одной программе получить возможности другой: список городов, праздники, статус доставки. Запрос проходит путь UI → сервис → API-клиент → внешняя система. Ответ возвращается в обратном порядке.

### Запрос и договор

```python
import requests

def fetch_items(url):
    response = requests.get(url, params={"limit": 5}, timeout=10)
    response.raise_for_status()
    return response.json()
```

Это функция для адреса из документации выбранного API, а не готовая интеграция с вымышленным сервисом. `params` кодирует параметры URL, `headers` передаёт служебные данные. `raise_for_status` проверяет ошибочные HTTP-статусы. `json` разбирает тело, но не проверяет ожидаемые поля.

Успешный HTTP-статус не означает правильные бизнес-данные. Ответ может оказаться пустым, иметь другую структуру или содержать неподходящий тип. Проверяйте форму ответа до обращения к полям.

### Три разных исхода

Пустой список означает «подходящих записей нет». Timeout означает «не дождались ответа». HTTP-ошибка означает, что сервер вернул ошибочный статус. Их нельзя превращать в один безмолвный пустой список.

`requests` различает Timeout, HTTPError и другие RequestException. Неверный JSON даёт JSONDecodeError. Таймаут ограничивает ожидание сетевых операций, но не является гарантией общего времени выполнения всего бизнес-сценария.

Повторять автоматически безопаснее чтение. Повтор запроса создания заказа может создать дубль; для таких операций нужен ключ идемпотентности или иной договор сервиса. Ключи API не выводят в сообщения и журнал вместе с URL.

### Изоляция интеграции

Пусть API-клиент возвращает City, а не произвольный внешний словарь. Тогда изменение названия поля внешнего сервиса затронет адаптер, а не все экраны. Для проверки логики используйте сохранённый искусственный ответ и не зависите от доступности интернета.

## Частые ошибки

Не используйте json() как доказательство успеха HTTP. Не превращайте исключение связи в «ничего не найдено». Не повторяйте создание платежа без защиты от дублей.

### Задача 1. Внутренняя модель

#### Условие

Преобразуйте искусственный ответ города в dataclass.

#### Как рассуждать и алгоритм

Сопоставьте внешние ключи с внутренними именами и проверьте типы.

#### Решение

```python
from dataclasses import dataclass
@dataclass
class City:
    name: str
    population: int

def parse_city(item):
    name = item.get("city_name")
    population = item.get("population")
    if not isinstance(name, str) or not name.strip():
        raise ValueError("Нет названия города")
    if type(population) is not int or population < 0:
        raise ValueError("Неверная численность")
    return City(name.strip(), population)
print(parse_city({"city_name": "Брянск", "population": 100}))
```

#### Проверка

Корректная запись даёт City. Отсутствующее имя, -1 и строка "100" отклоняются. Внешние данные здесь ожидаются словарём.

### Задача 2. Таймаут и статус

#### Условие

Получите JSON и отдельно сообщите о таймауте и HTTP-ошибке через собственные ошибки сценария.

#### Как рассуждать и алгоритм

Ловите конкретные исключения, сохраняя исходную причину. UI позже покажет сообщение.

#### Решение

```python
import requests

def load_data(url):
    try:
        response = requests.get(url, timeout=10)
        response.raise_for_status()
        return response.json()
    except requests.Timeout as error:
        raise RuntimeError("Сервис не ответил вовремя") from error
    except requests.HTTPError as error:
        raise RuntimeError("Сервис вернул ошибку") from error
```

#### Проверка

Функция не запускается без адреса. Подставьте тестовый клиент: Timeout должен стать одной ошибкой, HTTPError — другой. Неверный JSON и прочие сетевые ошибки не скрываются этой функцией.

### Задача 3. Фильтрация готового ответа

#### Условие

Из искусственного списка тарифов выберите доступные и отсортируйте по цене.

#### Как рассуждать и алгоритм

Сначала отделите проверку ответа API от бизнес-фильтра. Здесь список уже проверен.

#### Решение

```python
def available_tariffs(items):
    available = [item for item in items if item["available"]]
    return sorted(available, key=lambda item: item["price"])
items = [{"name": "A", "price": 200, "available": False},
         {"name": "B", "price": 300, "available": True}]
print(available_tariffs(items))
```

#### Проверка

Вернётся только B. Пустой список — допустимый результат без сетевой ошибки.
