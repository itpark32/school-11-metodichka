# Модули и структура небольшого приложения

<p class="reading-time">Примерное время · Чтение: 5–7 мин · Практика: 40–65 мин</p>

!!! abstract "Фокус"
    - **Нужно знать:** `import`, модуль, точка входа, зависимости.
    - **Нужно уметь:** разделить расчёт, интерфейс и хранение по файлам.

## Теория

Когда меню, расчёты и запись данных лежат в одном файле, изменение интерфейса легко ломает вычисления. Модуль — файл Python с отдельной понятной ответственностью.

### Минимальная структура

```text
shop/
├── main.py       # запуск меню
├── pricing.py    # расчёт стоимости
└── storage.py    # чтение и запись
```

В `pricing.py` объявляют `calculate_total`. В `main.py` пишут `from pricing import calculate_total`. Не называйте свой файл `json.py`, `requests.py` или `telebot.py`: он может закрыть установленный модуль с тем же именем.

### Импорт не должен запускать меню

```python
def main():
    print("Меню приложения")

if __name__ == "__main__":
    main()
```

При прямом запуске файла `__name__` равен `"__main__"`. При импорте функция объявится, но меню не начнёт требовать ввод. Код верхнего уровня модуля выполняется при первом импорте, поэтому там не место запуску бота и запросам пользователя.

### Направление зависимостей

Интерфейс вызывает расчёт. Расчёт не импортирует интерфейс. Если `main` импортирует `storage`, а `storage` пытается импортировать данные из `main`, появляется циклическая зависимость. Общую модель вынесите в отдельный модуль, а нужные значения передавайте параметрами.

Зависимости проекта устанавливают в виртуальное окружение. Список фиксируют в `requirements.txt`; его нельзя путать с `requirements-docs.txt`, который нужен для сайта методички.

## Частые ошибки

Не устанавливайте пакеты в случайный интерпретатор: используйте `python -m pip`. Не храните данные между модулями через импорт main. Не выполняйте input при импорте библиотеки.

## Разбор практических задач

Сначала составьте свой план решения. Затем сравните его с разбором и проверьте результат.

### Задача 1. Отделить расчёт

#### Условие

Вынесите налог учебного счёта в функцию, не использующую ввод и печать. Ставку передавайте явно.

#### Как рассуждать и алгоритм

В модуле расчётов оставьте только вычисление. В примере все суммы в целых копейках.

#### Решение

```python
# pricing.py
def add_fee(amount, percent):
    return amount + amount * percent // 100
```

#### Проверка

Вызов add_fee(10000, 5) вернёт 10500. При ставке 0 вернётся исходная сумма. Округление здесь вниз по учебному договору.

### Задача 2. Точка входа

#### Условие

Используйте pricing.py из предыдущей задачи, не запуская интерфейс при импорте.

#### Как рассуждать и алгоритм

Создайте main.py рядом с pricing.py. Запуск поместите под проверку имени модуля.

#### Решение

```python
# main.py
from pricing import add_fee

def main():
    print(add_fee(10000, 5))

if __name__ == "__main__":
    main()
```

#### Проверка

`python main.py` печатает 10500. `python -c "import main"` ничего не печатает.

### Задача 3. Передать хранилище

#### Условие

Сервис должен работать со списком товаров, который передан извне.

#### Как рассуждать и алгоритм

Функция не должна искать глобальный каталог. Так можно подставить небольшой набор для проверки.

#### Решение

```python
def find_product(products, sku):
    for product in products:
        if product["sku"] == sku:
            return product
    return None
print(find_product([{"sku": "A", "price": 100}], "A"))
```

#### Проверка

A возвращает словарь товара; B и пустой каталог дают None. Печать результата не входит в функцию поиска.

## Самостоятельная практика

Разделите каталог на main.py, models.py, services.py и storage.py. Нарисуйте стрелки импортов. Проверьте, что импорт сервисов не открывает меню и не создаёт файлов.
