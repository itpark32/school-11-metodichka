# Даты, типы и безопасная проверка ввода

!!! abstract "Фокус"

    - **Нужно уметь:** разделять проверку формата и бизнес-ограничения, повторно использовать валидатор.

## Теория

Пользователь вводит строки, а программе нужны числа, даты и выбранные значения. Надёжный порядок: очистить ввод → преобразовать → проверить ограничение → принять данные. Ошибка не должна частично менять каталог.

### Проверка формата не равна правилу

Int("-3") успешно даёт число, но отрицательное количество недопустимо. Float("nan") тоже выполняется, однако NaN не является конечной ценой или рейтингом. Для float проверяйте math.isfinite, затем диапазон. Для денежных расчётов в наших упражнениях используются целые копейки.

### Дата как значение

```python
from datetime import date, datetime
text = "07.11.2026"
visit_date = datetime.strptime(text, "%d.%m.%Y").date()
print(visit_date.strftime("%Y-%m-%d"))
```

Strptime разбирает строку и проверяет существование даты, strftime создаёт строковое представление. Date хранит календарную дату, datetime — дату и время. Сравнивайте объекты дат, а не строки вида ДД.ММ.ГГГГ: порядок текста отличается от календарного.

### Диапазон и сообщение

После разбора проверьте minimum<=value<=maximum. Разделите функции: parse_date получает текст и возвращает date или None; функция консольного ввода повторяет запрос и показывает сообщение. Тот же парсер позже использует бот.

### Локальное время и данные API

Дата выпуска товара — календарная дата без времени. Время внешнего события может требовать часового пояса. Не отбрасывайте время через .date(), если пользователю нужна точная отметка события. В первом курсе достаточно явно называть, что именно хранится.

### Изменяем данные после проверки

Сначала сформируйте новую допустимую запись, затем заменяйте старую. Если пользователь ошибся в последнем поле, исходный объект не должен остаться с половиной уже обновлённых полей. UI и сервис отвечают за разные границы проверки.

## Частые ошибки

Не сравнивайте календарные даты строками. Не ловите исключение пустым except. Float может принять бесконечность и NaN. Не изменяйте запись по частям до завершения проверки.

## Разбор практических задач

Сначала запишите свой план и ожидаемый результат, затем сравните с разбором.

### Задача 1. Календарная дата

#### Условие

Разберите дату либо верните None при неверном формате/несуществующем дне.

#### Как рассуждать и алгоритм

Ловите ValueError от strptime, остальные ошибки кода не скрывайте.

#### Решение

```python
from datetime import datetime

def parse_date(text):
    try:
        return datetime.strptime(text.strip(), "%d.%m.%Y").date()
    except ValueError:
        return None
print(parse_date("31.02.2026"))
```

#### Проверка

31.02.2026 → None, 28.02.2026 → date, 29.02.2024 принимается.

### Задача 2. Конечный рейтинг

#### Условие

Допустим рейтинг 1..5, включая дробные значения.

#### Как рассуждать и алгоритм

После float проверьте конечность и диапазон.

#### Решение

```python
import math

def parse_rating(text):
    try:
        value = float(text)
    except ValueError:
        return None
    return value if math.isfinite(value) and 1 <= value <= 5 else None
print(parse_rating("4.7"), parse_rating("nan"))
```

#### Проверка

4.7 принимается; nan, inf, abc, 0 и 6 отклоняются.

### Задача 3. Период

#### Условие

Проверьте согласованность начала и конца периода.

#### Как рассуждать и алгоритм

Вход уже содержит date. Проверка диапазона не зависит от формата вывода.

#### Решение

```python
from datetime import date

def valid_period(start, finish):
    return start <= finish
print(valid_period(date(2026, 11, 1), date(2026, 11, 7)))
```

#### Проверка

Одинаковые даты допустимы. Начало после конца даёт False.
