Большой проект легче развивать, если каждый файл и каждая функция имеют одну понятную ответственность.

!!! abstract "Фокус"
    - **Нужно знать:** ответственность файла, модуль, импорт и контракт функции.
    - **Часто в работе:** разделение модели, правил, ввода и пользовательского сценария.
    - **Достаточно узнавать:** более сложные архитектурные шаблоны.

## Разделение по ролям

```text
shop/
├── main.py                # меню и сценарии пользователя
├── product.py             # модель Product
├── products_functions.py  # операции над каталогом
└── console_helper.py      # безопасный ввод и оформление
```

- модель знает, из каких данных состоит товар;
- функции каталога ищут, добавляют, изменяют, удаляют и сортируют;
- консольные помощники проверяют ввод;
- `main.py` связывает шаги в пользовательский сценарий.

## Данные движутся через функции

```text
ввод → проверка → Product → операция с products → результат → вывод
```

Например, добавление не должно целиком жить в одной огромной ветке меню: UI получает значения, `input_product_data()` создаёт объект, `get_next_product_id()` назначает ID, а `add_product_to_list()` меняет каталог.

## Контракт функции

До реализации запишите:

- что функция получает;
- что возвращает;
- что изменяет;
- что считается ошибкой.

```python
def buy_product(products, search_id, request_amount) -> bool:
    """Уменьшает остаток; False — товар не найден или его недостаточно."""
```

Так вызывающий код знает результат, не разбирая внутреннюю реализацию.
