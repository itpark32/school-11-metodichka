# Модули, ответственность и договоры частей приложения

<p class="reading-time">Примерное время · Чтение: 4–6 мин · Практика: 40–65 мин</p>

!!! abstract "Фокус"
    - **Нужно знать:** модель, операции, хранилище, UI, точка входа и зависимость.
    - **Нужно уметь:** проследить данные и заменить интерфейс без переписывания расчёта.

## Теория

Архитектура — распределение ответственности, а не обязательный набор красивых папок. Когда меню, проверки, расчёт и запись смешаны, одну функцию трудно проверить отдельно. Разделение помогает читать и развивать приложение.

### Четыре роли

```text
models.py       структура одной записи
services.py     операции и бизнес-правила
storage.py      загрузка и сохранение
main.py         ввод, меню и сообщения
```

В проектах занятий имена могли быть product.py, products_functions.py и console_helper.py. Роль важнее имени. Один файл не обязан превращаться в класс ради архитектуры.

### Данные идут через параметры и результат

UI читает строку → парсер возвращает допустимое значение → модель собирает запись → сервис выполняет правило → хранилище сохраняет → UI показывает итог. Если сервис сам вызывает input, его нельзя спокойно использовать в боте или тесте.

### Контракт функции

До кода запишите вход, выход, изменения и отказ. Например, sell(products,id,quantity) получает каталог, возвращает bool, уменьшает остаток только при успехе. Хранилище не должно спрашивать подтверждение пользователя, а UI не должен разбирать служебный файл.

### Направление импортов

Main может импортировать services и storage. Models не должен импортировать main ради общего списка. Это создаёт циклические зависимости и неожиданный запуск интерфейса при импорте. Общие типы держите отдельно, данные передавайте явно.

### Вертикальный сценарий

Сначала соберите одно действие полностью: пункт меню → проверка → добавление → вывод. Затем подключите сохранение этого действия. Десятки функций с pass ещё не дают работающий сценарий. Заглушка полезна, если обозначает договор и используется для временной проверки.

## Частые ошибки

Не храните общие данные импортом из main. Не смешивайте ошибки загрузки с пустым каталогом. Заглушка не должна выдавать фиктивный успех.

## Разбор практических задач

Сначала запишите свой план и ожидаемый результат, затем сравните с разбором.

### Задача 1. Карта ответственности

#### Условие

Распределите чтение цены, расчёт итога и запись JSON по модулям.

#### Как рассуждать и алгоритм

Выбирайте роль по действию, а не по тому, где удобнее дописать строку.

#### Решение

```text
input/сообщения → UI
преобразование цены → парсер/помощник ввода
расчёт итоговой суммы → сервис
формат JSON и запись файла → хранилище
поля записи → модель
```

#### Проверка

Ни один модуль не должен одновременно требовать пользовательский ввод и решать все остальные задачи.

### Задача 2. Передаваемая зависимость

#### Условие

Сервис отчёта должен получать функцию загрузки извне.

#### Как рассуждать и алгоритм

Так можно подставить учебный набор без реального файла.

#### Решение

```python
def total_stock(load_products):
    products = load_products()
    return sum(item["stock"] for item in products)
print(total_stock(lambda: [{"stock": 3}, {"stock": 5}]))
```

#### Проверка

Результат 8. Пустой загрузчик lambda:[] даёт 0.

### Задача 3. Точка входа

#### Условие

Импорт main не должен сразу запускать меню.

#### Как рассуждать и алгоритм

Поместите запуск под проверку __name__.

#### Решение

```python
def main():
    print("Меню каталога")
if __name__ == "__main__":
    main()
```

#### Проверка

Прямой запуск печатает меню. Импорт файла лишь определяет функцию.
