## Теория

Событие описывает то, что произошло: команда, обычный текст или нажатие Inline-кнопки. Handler — функция-реакция. Важен не код одной игры или каталога, а порядок: определить событие → получить данные → проверить → изменить модель → показать результат.

### Разные события

| Действие | Что приходит | Чем обрабатывать |
|---|---|---|
| /help | Message с командой | message_handler(commands=...) |
| Текст пользователя | Message | message_handler(content_types=...) |
| Reply-кнопка | Обычный текст в Message | Текстовый фильтр |
| Inline-кнопка | CallbackQuery | callback_query_handler |

Reply-клавиатура расположена под полем ввода, Inline прикреплена к сообщению. Видимая подпись и callback_data имеют разные роли: подпись для человека, данные — для программы. Нажатие одной Reply-кнопки нельзя считать отдельным защищённым протоколом: такой же текст можно набрать вручную.

### Функция-фильтр

Декоратор регистрирует обработчик. Func получает событие и возвращает bool: подходит ли оно. Lambda здесь — короткая функция. Специальные команды регистрируются перед общим текстовым обработчиком, иначе широкий фильтр перехватит запрос.

### Chat и пользователь

Message.chat.id определяет чат для ответа, from_user.id — автора. В группе чат один, авторы разные. Контекст личного сценария нельзя хранить только по chat.id. В темах группы у сообщения может быть message_thread_id; чтобы ответ остался в той же теме, передавайте этот ID, когда он есть.

### Payload как маленький протокол

Код service:7 можно разобрать на действие и ID. Проверяйте префикс, число и существование записи. Данные кнопки могут устареть: товар удалили, пользователь вернулся к старому сообщению. Callback_data не даёт права изменять чужую запись.

### Ответ на callback и изменение сообщения

Answer_callback_query завершает индикатор ожидания кнопки. Send_message отправляет новое сообщение, edit_message_text меняет существующее, edit_message_reply_markup позволяет заменить/убрать клавиатуру. Это разные действия: функция с именем hide_keyboard не скрывает кнопки сама, если внутри только send_message.

### Текст и медиа

Send_message отправляет текст, send_photo — изображение с необязательной подписью caption. Источником фото может быть подходящий URL или открытый бинарный файл. Подпись относится к изображению и не является отдельным сообщением.

```python
# Фрагмент обработчика; message и bot уже определены
with open("service-photo.png", "rb") as photo:
    bot.send_photo(message.chat.id, photo, caption="Услуга: упаковка")
```

Режим rb открывает бинарные данные; with закрывает файл после отправки. Путь считается от рабочей папки процесса. Отсутствие файла и ошибка Telegram — разные причины отказа, которые нужно обработать на соответствующей границе. Не создавайте новое фото или случайный выбор повторно при проверке уже показанной карточки: сохраняйте нужный ID в контексте.

### Повторное нажатие

Если действие меняет данные, повтор не должен случайно дублировать операцию. Проверяйте актуальное состояние и признак обработки. Для серьёзной записи требуется договор хранилища, а не только локальная блокировка кнопки.

Фрагменты ниже добавляются к bot из [базовой главы](telegram.md) до запуска polling. Они не являются отдельными программами.

## Частые ошибки

Не путайте Message.text и CallbackQuery.data. Не забывайте answer_callback_query. Не сохраняйте единственный глобальный заказ для всех. Не принимайте ID кнопки без проверки.

## Разбор практических задач

### Задача 1. Разбор callback

#### Условие

Из service:7 получите числовой ID, остальное отклоните.

#### Как рассуждать и алгоритм

Не обращайтесь к каталогу до проверки формата.

#### Решение

```python
def parse_service_callback(data):
    if not isinstance(data, str):
        return None
    prefix, separator, value = data.partition(":")
    if prefix != "service" or not separator:
        return None
    try:
        identifier = int(value)
    except ValueError:
        return None
    return identifier if identifier > 0 else None
print(parse_service_callback("service:7"))
```

#### Проверка

service:7 → 7; service:abc, other:7, service:0 и None → None.

### Задача 2. Убрать клавиатуру

#### Условие

По кнопке hide удалите Inline-кнопки сообщения.

#### Как рассуждать и алгоритм

Ответьте на callback, затем измените reply_markup у нужного сообщения.

#### Решение

```python
# После создания bot, до polling
@bot.callback_query_handler(func=lambda call: call.data == "hide")
def hide_buttons(call):
    bot.answer_callback_query(call.id)
    if call.message is None:
        return
    bot.edit_message_reply_markup(
        chat_id=call.message.chat.id,
        message_id=call.message.message_id,
        reply_markup=None,
    )
```

#### Проверка

У сообщения исчезают кнопки. Нужна Inline-кнопка с callback_data="hide". Ошибку API при уже удалённом сообщении обрабатывает внешний сценарий.

### Задача 3. Сохранить контекст пользователей

#### Условие

Разделите данные двух людей в общем чате.

#### Как рассуждать и алгоритм

Ключ контекста содержит чат и автора.

#### Решение

```python
sessions = {}
sessions[(100, 1)] = {"service_id": 7}
sessions[(100, 2)] = {"service_id": 8}
print(sessions[(100, 1)]["service_id"])
```

#### Проверка

Для пользователя 1 получается 7, для 2 — 8. Память исчезнет при перезапуске.
