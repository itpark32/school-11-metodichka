# Рекурсия, стек вызовов и вложенные данные

<p class="reading-time">Примерное время · Чтение: 5–7 мин · Практика: 30–50 мин</p>

!!! abstract "Фокус"
    - **Нужно знать:** базовый случай, рекурсивный шаг, return и порядок возвратов.
    - **Нужно уметь:** проследить вызовы и выбрать рекурсию для вложенной структуры.

## Теория

Рекурсивная функция вызывает саму себя для меньшей части задачи. Это удобно, когда данные уже вложены: категория содержит подкатегории, задача — подзадачи. Для обычного суммирования списка цикл обычно проще.

### Условие остановки и приближение к нему

```python
def sum_to(number):
    if number < 0:
        raise ValueError("Нужно неотрицательное число")
    if number == 0:
        return 0
    return number + sum_to(number - 1)
```

Ноль — базовый случай. Уменьшение number на единицу приближает к нему. Проверка отрицательного входа не позволяет уйти в бесконечный спуск. Если вычисленный результат вложенного вызова не вернуть или не использовать, цепочка вычисления потеряет смысл.

### Вызовы имеют свои локальные переменные

При sum_to(3) возникают отдельные вызовы для 3, 2, 1 и 0. Каждый ждёт результат следующего. После возврата нуля получаем 1+0, затем 2+1, затем 3+3.

```text
sum_to(3)
  3 + sum_to(2)
        2 + sum_to(1)
              1 + sum_to(0)
                    0
Возврат: 0 → 1 → 3 → 6
```

Строка после рекурсивного вызова выполняется во время возврата, а до него — во время спуска. Поэтому печать до и после вызова даёт разный порядок.

### Вложенные структуры

Категорию можно описать словарём с названием и списком дочерних категорий. Лист дерева — категория без детей. Рекурсивный обход применяет то же действие к каждому ребёнку. Контракт должен исключать циклические ссылки: если категория содержит саму себя, обычный обход не завершится.

### Ограничения

У Python есть ограничение глубины вызовов. Переписать обход огромной цепочки рекурсией не значит ускорить его. Не увеличивайте лимит вместо исправления отсутствующей остановки. Для линейного набора используйте цикл, для вложенных данных сначала оцените глубину.

## Частые ошибки

Не забывайте остановку и возврат результата. Не используйте рекурсию там, где простой цикл понятнее. Не обходите циклические данные без контроля посещённых узлов.

## Разбор практических задач

Сначала запишите свой план и ожидаемый результат, затем сравните с разбором.

### Задача 1. Сумма до числа

#### Условие

Для неотрицательного n вычислите сумму 1..n.

#### Как рассуждать и алгоритм

Используйте меньшую задачу sum_to(n-1), а для нуля верните 0.

#### Решение

```python
def sum_to(n):
    if n < 0:
        raise ValueError("n < 0")
    return 0 if n == 0 else n + sum_to(n - 1)
print(sum_to(5))
```

#### Проверка

5 → 15; 0 → 0; -1 вызывает ValueError.

### Задача 2. Число подзадач

#### Условие

У задачи есть список children. Посчитайте все задачи, включая корень.

#### Как рассуждать и алгоритм

Каждый узел добавляет единицу и результаты обхода детей.

#### Решение

```python
def count_tasks(node):
    return 1 + sum(count_tasks(child) for child in node["children"])
project = {"children": [{"children": []}, {"children": []}]}
print(count_tasks(project))
```

#### Проверка

Результат 3. У одиночной задачи без детей результат 1.

### Задача 3. Обратный порядок этапов

#### Условие

Выведите вложенные этапы при возврате, а не при спуске.

#### Как рассуждать и алгоритм

Рекурсивный вызов поставьте раньше print. Сначала завершится самый глубокий вызов.

#### Решение

```python
def show_steps(n):
    if n <= 0:
        return
    show_steps(n - 1)
    print(n)
show_steps(3)
```

#### Проверка

Вывод 1, 2, 3. Перестановка print выше вызова даст 3, 2, 1.
