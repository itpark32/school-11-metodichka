## Теория

Сущность объединяет данные одного объекта предметной области. У товара есть название, цена, остаток и дата выпуска; у заявки — ID, услуга и статус. Отдельные списки названий и цен легко рассогласовать при удалении. Dataclass даёт полям имена и объединяет их в объект.

### Объявление и создание

```python
from dataclasses import dataclass

@dataclass(slots=True)
class Product:
    name: str
    price_kopecks: int
    stock: int = 0
    id: int | None = None

tea = Product("Чай", 15000, 5)
print(tea.name, tea.stock)
```

Класс описывает структуру, tea — конкретный объект. У обязательных полей нет значения по умолчанию; они идут перед полями с default. Декоратор создаёт __init__, читаемое __repr__ и сравнение по полям. Slots=True ограничивает набор атрибутов, но не проверяет тип присвоенного значения.

### Аннотация не является проверкой

Запись stock:int помогает редактору и человеку. Она сама по себе не запрещает stock="много". Для начальных ограничений можно использовать __post_init__, который dataclass вызывает после созданного конструктора.

```python
@dataclass
class Service:
    name: str
    price_kopecks: int

    def __post_init__(self):
        if not self.name.strip() or self.price_kopecks < 0:
            raise ValueError("Неверные данные услуги")
```

Эта проверка срабатывает при создании; последующее прямое присваивание полю её не запускает. Изменения проверяются сервисом или специально предусмотренным методом.

### Свои методы и независимые списки

Метод получает self — текущий объект. Для итоговой стоимости он может читать поля, не запрашивая ввод. Если поле хранит список, используйте field(default_factory=list): тогда у каждого объекта свой новый список. Не подставляйте один общий изменяемый список.

### ID и позиция

Поле id обозначает объект. Индекс обозначает его текущее место в списке. Сортировка меняет позицию, но не должна менять ID. До добавления в хранилище ID может отсутствовать, затем назначается по одному договору.

### Формат хранения

Asdict превращает dataclass в словарь, но не превращает date в JSON-строку и не сохраняет файл. Для хранения нужен отдельный формат и обратное восстановление типов. Представление __repr__ удобно для отладки, но не является надёжным файловым протоколом.

## Частые ошибки

Не путайте класс и объект. Аннотации не заменяют проверку. __post_init__ не перехватывает последующие присваивания. ID не должен зависеть от позиции.

## Разбор практических задач

Сначала запишите свой план и ожидаемый результат, затем сравните с разбором.

### Задача 1. Карточка услуги

#### Условие

Опишите услугу и её стоимость.

#### Как рассуждать и алгоритм

Свяжите поля в одном объекте, вычисление выполняйте по именам полей.

#### Решение

```python
from dataclasses import dataclass
@dataclass
class Service:
    name: str
    price: int
service = Service("Упаковка", 150)
print(service.price * 3)
```

#### Проверка

Итог 450 рублей. Другая услуга создаётся отдельным объектом.

### Задача 2. Свой список позиций

#### Условие

Два заказа не должны разделять одну коллекцию товаров.

#### Как рассуждать и алгоритм

Примените default_factory и измените список только первого заказа.

#### Решение

```python
from dataclasses import dataclass, field
@dataclass
class Order:
    items: list[str] = field(default_factory=list)
first = Order()
second = Order()
first.items.append("Чай")
print(second.items)
```

#### Проверка

Второй список остаётся пустым.

### Задача 3. Правило создания

#### Условие

Запретите отрицательный остаток при создании сущности.

#### Как рассуждать и алгоритм

__post_init__ проверяет объект сразу после инициализации.

#### Решение

```python
from dataclasses import dataclass
@dataclass
class Item:
    stock: int
    def __post_init__(self):
        if self.stock < 0:
            raise ValueError("Отрицательный остаток")
print(Item(0))
```

#### Проверка

0 допустим; Item(-1) вызывает ValueError. Проверку типа при необходимости добавляют отдельно.
