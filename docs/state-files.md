# Конечный автомат: состояния, события и переходы

<p class="reading-time">Примерное время · Чтение: 5–8 мин · Практика: 35–60 мин</p>

!!! abstract "Фокус"
    - **Нужно знать:** состояние, событие, контекст и допустимый переход.
    - **Нужно уметь:** описать сценарий до кода и проверить отказ без изменения данных.

## Теория

Состояние сообщает, на каком шаге находится программа. Событие — что сделал пользователь. Переход определяет следующий шаг. Контекст хранит уже введённые значения. Эти понятия встретились в квесте, но нужны и анкете, заказу или записи клиента.

### Одинаковый ввод имеет разный смысл

В меню сообщение 1 может открыть каталог, а на шаге количества означать одну услугу. Нельзя выбирать действие только по тексту без текущего состояния.

```text
menu → ввод названия → ввод количества → подтверждение → menu
                       ошибка ввода ↺
любой шаг → отмена → menu
```

Перед кодом составьте таблицу: текущее состояние, событие, проверка, изменение данных и следующий шаг. Неправильный ввод обычно оставляет пользователя на том же шаге.

### Переход как отдельная функция

```python
def next_state(state, event):
    transitions = {
        ("menu", "create"): "input_name",
        ("input_name", "valid_name"): "input_quantity",
        ("input_quantity", "valid_quantity"): "confirm",
        ("confirm", "accept"): "menu",
    }
    if event == "cancel":
        return "menu"
    return transitions.get((state, event), state)
```

Функция описывает переходы без input и print, поэтому её удобно проверить. Допустимость самого имени/количества проверяется отдельным кодом, который создаёт событие valid_name или valid_quantity.

### Состояние отдельно от данных

Контекст может иметь вид `{"name": "Упаковка", "quantity": 3}`. Смена состояния не сохраняет контекст в файл и не оформляет заказ. Запись выполняют после подтверждения, а отмена очищает черновик.

### Главный цикл

Консольный цикл получает событие и вызывает нужный обработчик состояния. У обработчика небольшой договор: получить контекст и ввод → проверить → вернуть результат. Это проще, чем десятки вложенных if с общей переменной, смысл которой меняется.

В Telegram та же идея применяется отдельно к каждому пользователю. Библиотечная FSM помогает хранить состояния, но не решает за разработчика, что разрешено и когда сохранять запись.

## Частые ошибки

Не путайте состояние с введёнными значениями. Не переводите шаг до проверки ввода. Смена состояния в памяти не является записью в файл.

## Разбор практических задач

Сначала запишите свой план и ожидаемый результат, затем сравните с разбором.

### Задача 1. Таблица переходов

#### Условие

Составьте переходы заявки new → in_progress → done.

#### Как рассуждать и алгоритм

Из состояния done продолжение работы без нового сценария не разрешено.

#### Решение

```text
new + start → in_progress
in_progress + finish → done
done + finish → done, повторной записи нет
любое состояние + неизвестное событие → без изменения
```

#### Проверка

Для каждого события должен быть указан результат. Это спецификация, а не Python-код.

### Задача 2. Проверить шаг

#### Условие

Получите количество только на ожидаемом шаге.

#### Как рассуждать и алгоритм

Сначала проверьте состояние, затем формат/диапазон. Изменяйте контекст после всех проверок.

#### Решение

```python
def set_quantity(context, text):
    if context["state"] != "quantity":
        return False
    try:
        quantity = int(text)
    except ValueError:
        return False
    if quantity <= 0:
        return False
    context.update(state="confirm", quantity=quantity)
    return True
```

#### Проверка

Для abc и 0 состояние остаётся quantity. Для 3 — confirm, quantity=3.

### Задача 3. Отмена черновика

#### Условие

Верните контекст к меню без сохранения заказа.

#### Как рассуждать и алгоритм

Очистите временные данные и установите единственное начальное состояние.

#### Решение

```python
def cancel(context):
    context.clear()
    context["state"] = "menu"
context = {"state": "confirm", "quantity": 3}
cancel(context)
print(context)
```

#### Проверка

Остаётся только state=menu. Повторная отмена даёт тот же результат.
