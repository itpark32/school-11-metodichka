# Консольный интерфейс: меню, роли и безопасный ввод

<p class="reading-time">Примерное время · Чтение: 4–7 мин · Практика: 40–65 мин</p>

!!! abstract "Фокус"
    - **Нужно знать:** цикл меню, команда выхода, парсер, сообщение об отказе и роль пользователя.
    - **Нужно уметь:** связывать готовые операции со сценарием, сохраняя расчёт отдельно.

## Теория

Консольный UI показывает данные, получает команды и объясняет результат. Его задача — помочь пользователю выполнить действие. Умение писать функции каталога не заменяет проектирование понятного пути через меню.

### Одна команда — один шаг

```text
Главное меню → каталог → поиск → карточка → покупка → результат
            → администратор → добавление → результат
```

У каждого подменю есть явный возврат. Пользователь должен понимать, выйдет 0 из программы или только вернёт на уровень выше. Не запускайте меню рекурсивно после каждой команды: вложенные вызовы будут накапливаться.

### Парсер и повторный запрос

Функция parse_int проверяет строку и возвращает значение/None. Обёртка input_int повторяет ввод и показывает причину. Это позволяет применять тот же парсер в боте. Не называйте локальную переменную input или list: она перекроет встроенное имя.

### Вывод и данные

Таблица для человека форматирует поля по ширине. При пустом каталоге покажите понятный текст. Для длинных названий и эмодзи учитывайте, что длина строки не всегда равна ширине терминала. Формат печатного отчёта не должен становиться служебным протоколом хранения.

### Роли и правила

Разные меню покупателя и администратора помогают показать разные действия. Скрытая кнопка или пункт меню не являются полноценной проверкой прав: если действие защищено, его сервис тоже проверяет право вызова. Простой учебный пароль из исходника — только заглушка, а не готовая система авторизации.

### Сообщение после результата

Сначала вызов операции и проверка её ответа, затем «Товар удалён» или «Не найден». Если запись не сохранилась, нельзя показывать «Сохранено». Подробности ошибок полезны разработчику, пользователю — понятное следующее действие.

## Частые ошибки

Не смешивайте меню с файловым форматом. Не вызывайте main из main для повторения. Не выдавайте учебный пароль за реальную авторизацию. Не теряйте введённые данные при ошибке.

## Разбор практических задач

Сначала запишите свой план и ожидаемый результат, затем сравните с разбором.

### Задача 1. Команда меню

#### Условие

Принимайте только целый пункт 0..3.

#### Как рассуждать и алгоритм

Парсер не печатает и не спрашивает, а только проверяет вход.

#### Решение

```python
def parse_command(text):
    try:
        value = int(text)
    except ValueError:
        return None
    return value if 0 <= value <= 3 else None
print(parse_command("2"), parse_command("abc"))
```

#### Проверка

2 и None. 0 допустим, 4 отклоняется.

### Задача 2. Пустой отчёт

#### Условие

Выведите таблицу услуг либо понятное сообщение.

#### Как рассуждать и алгоритм

Пустой список обрабатывается до заголовка/перебора либо с явной подписью.

#### Решение

```python
def show_services(items):
    if not items:
        print("Услуг пока нет")
        return
    print(f"{'ID':<5}{'Название':<20}")
    for item in items:
        print(f"{item['id']:<5}{item['name']:<20}")
show_services([])
```

#### Проверка

Пустой список даёт один текст. Две записи дают две строки под заголовком.

### Задача 3. Успех по результату

#### Условие

Покажите сообщение об удалении после проверки bool.

#### Как рассуждать и алгоритм

Не считайте сам вызов доказательством удаления.

#### Решение

```python
def deletion_message(deleted):
    return "Запись удалена" if deleted else "Запись не найдена"
print(deletion_message(False))
```

#### Проверка

False → «Запись не найдена», True → «Запись удалена». Реальная операция вызывается отдельно.
